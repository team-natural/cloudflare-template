# 01-contract-policy.md — 契約ポリシーテンプレート

## このセクションの目的

Web サイトの受託制作 + 運用保守契約における利用規約・SLA・契約変更・データ取扱い・損害賠償・免責を定義する。本テンプレートは 00_README §0-1 の**パターン A**（コンテンツ主体サイト + 軽量な管理画面）を前提とし、収益モデルは受託制作（初期構築費）+ 月額保守（BIZ-03 参照）である。Organization 単位のサブスクリプション契約は本テンプレートの対象外。**法務確認必須** 項目を多数含むため、最終確定前に弁護士レビューを受けること。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Human-first または Hybrid
- 人間確認必須: 法務表現、補償条件、データ返却・削除方針

## 2. 契約の主要条項

### 2-1. 提供サービスの定義

<!-- SAMPLE START: フォーマット例 — 実際のサービス名・内容に置き換えてください -->
- 「[サービス名]」とは、クライアントのコーポレートサイト/サービス LP/ブログ・お知らせ等を制作し、契約に応じて継続的に運用保守するサービスを指す
- サービス内容（対応範囲）は契約書・見積書に明記した範囲に限る。範囲外の作業はスポット対応（BIZ-03 §2-4）として別途見積もる
<!-- SAMPLE END -->

### 2-2. 発注者の責任

- 提供する原稿・画像等のコンテンツが正確であり、第三者の著作権・商標権・プライバシーを侵害しないこと
- 管理画面（`admin` / `editor`）のアカウント情報（ID / パスワード）の管理責任
- 契約範囲外の要望は都度見積もりの対象となることの了承

### 2-3. 知的財産権

| 区分 | 取扱い |
| --- | --- |
| サイト本体（デザイン・コード・テンプレート） | 検収完了後、契約書に定める範囲でクライアントに譲渡または利用許諾（要法務確認） |
| クライアント提供コンテンツ（Post/Page/Media） | クライアントが著作権保持。サイト掲載のための利用許諾を受ける |
| 自社の既存テンプレート・ノウハウ（本テンプレート自体） | 自社が保持。個別案件への利用許諾のみ行う |
| AI 生成物（採用時） | クライアントが独占的利用権を取得（利用規約に明記、要法務確認） |

### 2-4. データの取扱い

| データ | 取扱い |
| --- | --- |
| AdminUser 情報 | サービス提供目的のみ |
| Post / Page / Media | クライアントの資産として扱う。契約終了時の取扱いは §4-2 参照 |
| Inquiry（お問い合わせ内容） | サービス提供目的のみ。個人情報保護法に従い取扱う（DEV-02 参照） |
| 操作ログ（`activity_log`） | サービス改善・障害調査目的 |
| 決済情報（軽量 EC 採用時） | 取得しない（決済代行事業者へ委託 — DEV-01 §2 参照） |
| AI プロンプト（採用時） | LLM プロバイダへ送信、各プロバイダのポリシーに従う |

### 2-5. LLM 利用への同意（AI 機能採用時のみ）

<!-- TEMPLATE: LLM/AI を使う機能を実装する場合は必須。利用者が同意する送信先・ポリシーを列挙する -->
<!-- SAMPLE START: フォーマット例 — 利用する LLM プロバイダに置き換えてください -->
AI 機能（記事検索・要約等）を採用する場合、以下をクライアント・利用者に開示する：

- 入力データが [LLM プロバイダ名（例: Anthropic / OpenAI / Google）] に送信されること
- 各 LLM プロバイダのデータ取扱いポリシーが適用されること

LLM プロバイダ変更時は 30 日前にクライアントへ通知する。
<!-- SAMPLE END -->

### 2-6. 禁止事項

- 違法行為への利用、第三者の権利侵害
- サイトを通じた第三者へのスパム的な大量送信・自動収集
- リバースエンジニアリング
- AI 出力の悪用（プロンプトインジェクション等、採用時）

## 3. SLA（サービスレベル）

### 3-1. 稼働率

可用性の数値目標は **PRD-02 §5-2 を正本** とし、本書では値を再掲しない。SLA として提示する際も PRD-02 §5-2 の目標値をそのまま用いる。

<!-- SAMPLE START: フォーマット例 — 保守プランと SLA 上の取扱いは実際の契約に合わせて変更してください -->
| サービス | SLA 上の取扱い | 計画停止除外 |
| --- | --- | --- |
| 公開サイト | PRD-02 §5-2 の月間稼働率目標を SLA 目標として提示 | 該当 |
| 管理画面 | PRD-02 §5-2 の月間稼働率目標を SLA 目標として提示 | 該当 |
| AI 機能（採用時） | ベストエフォート（LLM プロバイダ依存） | — |
<!-- SAMPLE END -->

### 3-2. 補償

<!-- TEMPLATE: 目標稼働率（PRD-02 §5-2: 99.5% / 99.9%）と補償開始閾値（下表では 99.0%）の間に緩衝域があるのは意図的な設計判断である。目標をわずかに下回った月に即座に補償が発生しないための余裕であり、欠陥ではない。ただしプロジェクト適用時には、保守プランの価格・契約規模・リスク許容度に合わせて補償開始閾値と減額率を必ず見直すこと（要法務確認）。また、補償の基準となる「目標値」が管理側 99.5% / 公開側 99.9%（PRD-02 §5-2）のどちらを指すかを適用時に明記すること -->
<!-- SAMPLE START: フォーマット例 — 補償条件は実際の契約・法務と相談して変更してください -->
| 月間稼働率 | 補償（保守契約 [プロプラン] 以上のみ） |
| --- | --- |
| 99.0% 以上 目標値未満 | 当月保守費の 10% 翌月減額 |
| 95.0% 以上 99.0% 未満 | 当月保守費の 25% 翌月減額 |
| 95.0% 未満 | 当月保守費の 50% 翌月減額 |

- [ベーシックプラン] は SLA 補償対象外（ベストエフォート）
- 補償は申し出制
- 計画停止・LLM プロバイダ障害・天災・クライアント起因は除外
<!-- SAMPLE END -->

### 3-3. 保守プラン別一次応答時間（本書が正本）

サポートの一次応答時間 SLA は **本表を正本** とし、OPS-02（運用ハンドブック）は本表を参照する。

<!-- SAMPLE START: フォーマット例 — プラン名と応答時間は BIZ-03 §2-2 と一致させてください -->
| 保守プラン | 一次応答 SLA |
| --- | --- |
| ベーシック | ベストエフォート（72 時間目安） |
| スタンダード | 24 時間以内 |
| プロ | 8 時間以内 |
<!-- SAMPLE END -->

- 一次応答は平日 9:00〜18:00 ベースで計測する。時間外・休日の受付は翌営業日起算とする（OPS-02 §0 の対応時間原則と整合）
- 受付チャネル・エスカレーションの運用は OPS-02 §1 を参照

### 3-4. 計画停止

- 原則：月 1 回まで、土日深夜帯（日本時間 1:00〜5:00）
- 通知：7 日前にメールでクライアントへ通知
- 実施手順：OPS-02 §3

## 4. 契約変更・終了

### 4-1. 保守プラン変更

<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
| 変更内容 | 反映タイミング | 課金 |
| --- | --- | --- |
| プラン変更（上位） | 即時 | 日割り計算で当月課金 |
| プラン変更（下位） | 翌月 1 日 | 翌月から新プラン額 |
| 保守契約の終了 | 契約満了時（BIZ-03 §5 の通知期間に従う） | 当月までは課金 |
<!-- SAMPLE END -->

### 4-2. 契約終了時のデータ取扱い

<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
| 状況 | データ保管 | エクスポート |
| --- | --- | --- |
| 保守契約の通常終了 | 終了後 1 年間保持 | 終了後 90 日以内に申請可能（Post/Page/Media を CSV / エクスポート形式で） |
| 終了 + 1 年経過 | 物理削除 | 不可 |
| サイトデータ削除依頼 | 依頼後 90 日で物理削除 | 90 日以内は可能 |
| 規約違反による契約解除 | 30 日後物理削除 | 30 日以内は可能 |
<!-- SAMPLE END -->

### 4-3. 返金ポリシー

<!-- SAMPLE START: フォーマット例 — 実際の返金ポリシーに置き換えてください -->
| 区分 | 方針 |
| --- | --- |
| 初期構築費 | 検収完了後は原則返金なし |
| 月額保守費 | 日割り返金なし、終了は翌月から |
| サービス全停止時 | 状況に応じて返金 |
<!-- SAMPLE END -->

## 6. 受託案件向けの追加条項

<!-- TEMPLATE: 受託案件で必要な追加条項。本テンプレートの主業態が受託制作のため、通常はこの節をそのまま使う -->

### 6-1. 知的財産権の帰属

- 開発成果物の著作権がクライアント or 自社のどちらに帰属するか（§2-3 参照）
- 既存テンプレート・ノウハウの利用権
- 第三者ライブラリのライセンス条項の明示

### 6-2. 検収条件

- 検収期間と通過基準
- 修補義務の範囲・期間
- 検収後の保守条件（保守契約へ移行するか、都度契約か）

### 6-3. 損害賠償の上限

- 直接損害に限る
- 上限は初期構築費 or 当月保守費 × N

## 7. 損害賠償・免責

| 区分 | 方針 |
| --- | --- |
| クライアント損害 | 直接損害に限り、当該月の保守費相当を上限 |
| 間接損害 | 免責 |
| 第三者の権利侵害 | 提供コンテンツに起因する場合はクライアントが責任を負う |
| LLM プロバイダ障害（採用時） | 免責 |
| 天災・通信障害 | 免責 |

## 12. 記入時チェックポイント

- BIZ-03 のプラン名（§2-1 初期構築、§2-2 保守）と本書の §3-3 / §4-1 / §4-2 が一致しているか（Free/Starter/Pro 等の旧 SaaS プラン名が残っていないか）
- 稼働率の数値が PRD-02 §5-2（正本）と二重管理になっていないか
- §3-2 の補償開始閾値を目標稼働率との緩衝域も含めて見直したか
- DEV-02 のデータ保管期限と §4-2 が整合しているか
- 法務確認チェックリスト（§11）が空欄でないか
- 受託案件の場合、§6 が記入されているか
- Organization・メンバー・テナント等、単一運営前提（PRD-01 §1-2）と矛盾する記述が残っていないか
