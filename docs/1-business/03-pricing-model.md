# 03-pricing-model.md — 価格モデルテンプレート

## このセクションの目的

料金体系、課金単位、無料提供範囲、価格改定条件、採算性の見方を定義する。本テンプレートが想定する主な業態は **Web サイトの受託制作 + 運用保守** であり、これを本書の主パターンとする。自社でメディア/コンテンツサイトを運営する場合は §8-2 の代替パターンを参照する。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Hybrid（AI 試案 + 事業責任者 / PdM 確認。兼務前提。対外条項のみ法務確認）
- 人間確認必須: 価格金額、契約条件、既存顧客の扱い、収益性の前提

## 3. 課金モデルの選定根拠

| 候補モデル | 採用 | 選定根拠 | 懸念点 |
| --- | --- | --- | --- |
| 初期構築費（買い切り） | **採用** | 制作という有形の成果物に対する対価として説明しやすい | 単発収益で終わり、継続収益にならない |
| 月額保守（リテイナー） | **採用** | 継続収益を作り、更新の内製化支援を価値として訴求できる | 保守稼働の見積を誤ると採算が合わない |
| 都度課金 | 部分採用 | 保守契約外の単発対応を受けられる | 請求予測が立ちにくい |
| サブスクリプション | 不採用 | 本テンプレの想定業態（受託制作）に馴染まない（自社メディア運営時は §8-2 で別途検討） | — |

## 4. 無料提供範囲・トライアル設計方針

<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
| 項目 | 内容 |
| --- | --- |
| 方式 | 無料トライアルは基本なし（受託制作のため）。提案時に無料でワイヤーフレーム/デザイン方向性の簡易案を提示することはある |
| 保守契約の試用 | 制作完了後 1 ヶ月間は保守費を無償提供し、対応範囲・応答速度を体感してもらう |
| 本契約への転換 | 無償期間終了時に保守プラン（§2-2）を選択。未選択の場合は監視のみの最小保守に自動移行 |
| 悪用防止策 | 該当なし（B2B 受託契約のため個人の悪用リスクは低い） |
<!-- SAMPLE END -->

## 5. 価格改定ポリシー

| 項目 | 方針 |
| --- | --- |
| 改定条件 | インフラ利用料の変動、対応範囲の拡大、市場相場の変化 |
| 通知期間 | 60 日前にメール通知 |
| 既存契約 | 次回契約更新時から新価格適用 |
| 改定通知後の解約権 | 通知後 30 日間は違約金なしで解約可 |

## 6. 収益性試算フレーム

### 6-1. ユニットエコノミクス

<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
**前提**: スタンダードプラン（初期構築 + 月額保守）1 件

| 項目 | 算式 | 値 |
| --- | --- | ---: |
| 初期構築収益 | 一括 | ¥800,000 |
| 初期構築原価 | 制作工数（人件費） | ¥400,000 |
| 初期構築粗利 | 収益 − 原価 | ¥400,000（粗利率 50%） |
| 月額保守収益 | 月額 | ¥40,000 |
| 月額保守原価 | 対応工数（人件費）+ インフラ利用料（DEV-01 参照。少数サイト規模では小さい） | ¥15,000 |
| 月額保守粗利 | 収益 − 原価 | ¥25,000（粗利率 63%） |
| 保守 LTV（継続率 90%） | 月次粗利 ÷ (1 − 継続率) | ¥250,000 |

※ 継続率 90% は**成長期**の想定値（BIZ-02 §3 KPI-02 の成長期目標と対応）。
<!-- SAMPLE END -->

### 6-2. 採算判断基準

- 初期構築の粗利率 40% 以上、保守の粗利率 60% 以上を目標（BIZ-02 KPI と整合）
- インフラコスト（Cloudflare 利用料）は少数サイト規模では軽微だが、サイト数が増える場合は DEV-01 §7 の依存関係管理方針に沿って定期的に確認する
- 保守対応工数が見積を超過し続ける契約は、プランの見直し（上位プランへの誘導）を検討する

---

## 7. 価格設計時の判断基準

- 顧客が比較対象とする代替手段（他制作会社、ノーコードサービス）より費用対効果が説明可能か
- 保守プランの対応範囲が工数見積と整合しているか（過小見積で赤字案件にならないか）
- 初期構築費が制作規模（ページ数・機能）で説明可能か
- PRD-03 の MVP 機能とプラン内容が整合しているか

## 8. 業態別のバリエーション

### 8-1. 受託案件向けの価格モデル（本書の主パターン）

<!-- TEMPLATE: 本節は受託案件（00_README §4-2 の受託フロー）で使用する -->

受託案件では「初期構築 + 保守」「完全買い切り」のバランスが論点。

| 受託パターン | 課金 |
| --- | --- |
| 初期構築 + 運用保守 | 初期費用（一括）+ 月額保守（§2-2） |
| 完全買い切り | 初期費用のみ、保守は別契約または対応なし |
| 共同開発 | 共同事業の収益分配 |

詳細はクライアントごとに検討、OPS-01 §6 で契約条件に落とし込む。

### 8-2. 自社運営メディア/コンテンツサイトの場合（代替パターン）

自社でコーポレートサイト・メディアサイトを運営し、直接課金しない場合は、収益源を以下のいずれかに読み替える。

| 収益源 | 内容 |
| --- | --- |
| 広告収益 | サイト内広告表示（アドネットワーク等） |
| アフィリエイト収益 | 紹介経由の成果報酬 |
| リード獲得 | サイトはコストセンターとして、獲得したリードを別事業の売上に接続 |

この場合、BIZ-02 の KPI-01〜03（受注件数・保守継続率・案件単価）は広告収益・アフィリエイト収益・リード獲得数等に読み替える。

## 9. 記入時チェックポイント

- 課金パターン（§1-1）の採否が明確か
- プラン差分（§2-3）が対応範囲の違いで説明できるか
- 保守対応の工数見積と月額保守費が採算的に整合しているか
- ユニットエコノミクスが現実的か
- 価格改定・解約・返金の方針が OPS-01 §4（解約・返金）・§5（価格改定）と整合しているか
- 自社運営メディアの場合、§8-2 の読み替えが BIZ-02 に反映されているか
