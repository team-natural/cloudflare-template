# 01-business-concept.md — 事業コンセプトテンプレート

## このセクションの目的

サービスの存在意義、解決する課題、顧客像、価値提供、事業フェーズを定義する起点文書。以降の KPI、価格設計、機能要件の判断軸をそろえる。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Hybrid（AI 初稿 + 事業責任者 / PdM レビュー。兼務前提）
- 人間確認必須: ターゲット顧客の定義、提供価値の差別化、前提条件・制約

## このドキュメントの使い方

以下の各セクションには `<!-- SAMPLE START / END -->` ブロックがあります。これらはすべてフォーマット確認用の例示です。**新規プロジェクトでは SAMPLE ブロックを削除し、あなたのプロジェクト情報に置き換えてください。**

必須は §1〜§3・§5〜§8。§4 と §6-2 は付録（任意）であり、最速リリースを優先する場合はスキップしてよい。

> 本テンプレートは **コンテンツ主体サイト**（コーポレートサイト・サービス LP・ブログ / お知らせ・ドキュメント）+ **軽量な管理画面**を前提とする（00_README §0-1 の判断基準を参照）。以下の SAMPLE はその前提で書かれている。マルチテナント SaaS・複雑な業務システムを作る場合は、本テンプレの適用範囲外（00_README §0-1・§2-2）。

## 1. 事業概要（エレベーターピッチ）

<!-- TEMPLATE: 5 要素を 1〜2 文ずつで -->
<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
- **誰のどんな課題を解決するか**: 中小〜中堅企業が、更新の遅い・検索に強くないコーポレートサイトのせいで、サービス内容が正しく伝わらず、問い合わせ（リード）を取り逃している課題を解決する。
- **提供する主要価値**: 表示速度・SEO に強いコーポレートサイト + サービス LP + ブログ/お知らせを一体で提供し、担当者が自分でブログ・お知らせを更新できる軽量な管理画面（CMS）を付ける。
- **競合代替手段との差分**: 汎用 CMS（WordPress 等）のプラグイン依存・表示速度劣化に対し、静的に近い配信（Astro SSR + Cloudflare エッジ）で初期表示が速く、更新のしやすさは損なわない点で優位。
- **収益化方法**: Web サイト制作の受託開発（初期構築費）+ 月額の運用保守（リテイナー）。
- **今なぜやるのか**: Core Web Vitals が検索順位・広告効果に直結する認識が広がり、遅い・古い CMS からの乗り換え需要が増えている今がタイミング。
<!-- SAMPLE END -->

<!-- SAMPLE START: フォーマット例 — 実際の競合に置き換えてください -->
| 競合カテゴリ | 代表例 | 強み | 弱み | 当社の勝ち筋 |
| --- | --- | --- | --- | --- |
| 直接競合 | 一般的な Web 制作会社（WordPress 中心） | 実績・テーマ資産が豊富、制作コストが安い | 表示速度・脆弱性対応が構造的に弱い | エッジ配信による表示速度 + 担当者が更新しやすい CMS |
| 部分競合 | ノーコード Web 制作サービス（Wix 等） | 自分で作れる手軽さ | 表示速度・カスタマイズ性に限界、SEO の伸びが弱い | 専門的な実装 + 内製更新のしやすさの両立 |

- **X 軸**: 表示速度・技術的な作り込みの強さ

## 7. 事業フェーズ定義

事業フェーズは全文書共通で **MVP 期 / 成長期 / 安定期** の 3 段階とし、BIZ-02 §3「フェーズ別 KPI 目標値」の列と 1:1 で対応させる。**移行条件の数値は BIZ-02 §3 を正本とし、本表では重複管理しない。**

<!-- TEMPLATE: フェーズごとの定義と主目的を記述。移行条件は BIZ-02 §3 への参照にとどめる -->
<!-- SAMPLE START: フォーマット例 — 実際の内容に置き換えてください -->
| フェーズ | 定義 | 主目的 | 移行条件 |
| --- | --- | --- | --- |
| MVP 期 | コア構成（公開サイト + ブログ/お知らせ + お問い合わせフォーム + 軽量 CMS）を提供 | サイト公開・初期の問い合わせ獲得の検証 | BIZ-02 §3 の MVP 期目標（オーガニック流入・問い合わせ件数等）を達成 |
| 成長期 | SEO/コンテンツ強化による流入拡大 | 問い合わせ件数の継続的な増加 | BIZ-02 §3 の成長期目標を達成 |
| 安定期 | 保守運用体制の効率化、複数サイトの横展開 | 保守案件数の安定化と対応効率化 | —（BIZ-02 §3 の安定期目標を維持） |

## 9. 記入時チェックポイント

- 誰の、どの課題を、どの場面で解決するかが明確か
- 価値仮説と価格仮説、要件仮説に矛盾がないか
- 除外スコープや前提条件が後続文書に引き継げる形で書かれているか
- ペルソナが具体的で、PRD-03 のユーザーストーリーに繋がるか
- フェーズ命名が「MVP 期 / 成長期 / 安定期」で統一され、移行条件が BIZ-02 §3 と二重管理になっていないか
- コンテンツ主体（パターン A）の前提から外れていないか（マルチテナント SaaS・複雑な業務ロジックが事業の中心になっていないか）
